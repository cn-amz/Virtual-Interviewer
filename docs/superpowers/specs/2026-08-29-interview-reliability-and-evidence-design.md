# 面试可靠性与证据评分设计

## 目标

把当前“能通话”的原型改成可稳定完成一场面试、正确保存对话并生成可解释报告的应用，同时保留百炼全双工能力和 MiniCPM 本地实验路径。

评分基准确定为：目标 JD 岗位胜任度占 70%，本场回答表现占 30%。每个评分结论必须引用本场问答证据；没有证据时只能标记“未覆盖”，不能推断为能力不足。

## 范围拆分

改造分为三个可独立验收的阶段：

1. 实时链路可靠性：Provider 状态、单一 ASR、轮次标识、自动滚动、退出与持久化。
2. 面试编排：时长、主题、阶段预算、单轮一个问题、可靠收尾。
3. 证据报告：清洗问答、逐维评分、失败重试、可解释报告和能力树更新。

三个阶段共享同一个会话控制模型，但不要求同时上线。每阶段完成后应用都必须可运行和可测试。

## 已确认决策

- 百炼保持全双工默认，不因一次自答现象退回半双工。
- 播放流与麦克风流不做默认互斥；提供“播放时暂停上传”诊断开关，用于排查特定声卡、蓝牙驱动或虚拟音频设备的回灌。
- 百炼只采用百炼上游 ASR。浏览器语音识别只作为 MiniCPM 当前缺少候选人 ASR 时的临时方案。
- 模型自答按面试官身份失守处理：候选人回答为空、迟疑或不知道时，只能简化、澄清或换题，禁止替答和教学。
- MiniCPM 与百炼继续使用同一个应用会话接口，但各自编译 Provider 专用提示词和能力状态。
- 报告模型失败时显示可重试错误，不再把规则兜底伪装成正式评估。

## 阶段一：实时链路可靠性

### Provider 就绪状态

后端增加只读 Provider 状态接口，统一返回：

```json
{
  "provider": "minicpm",
  "state": "idle",
  "detail": "模型已就绪",
  "queue_length": 0
}
```

`state` 只允许 `offline`、`loading`、`queued`、`idle`、`busy`、`error`。MiniCPM 状态由后端代理本地 Comni `/status`，前端不直接访问自签名 HTTPS。百炼在配置有效时返回 `idle`，连接错误仍由实际会话建立阶段报告。

设置页和面试页都显示具体状态。MiniCPM 为 `loading`、`busy` 或 `offline` 时禁止重复点击连接；状态恢复 `idle` 后允许重新连接。结束 MiniCPM 会话后的重载必须显示为“模型正在重置”，不能显示成普通断线。

### 单一候选人转写源

`InterviewSessionSelection.provider` 决定转写策略：

- `bailian`：不创建浏览器 `SpeechRecognition`，只接受 Provider 的 `transcript.partial/item`。
- `minicpm`：继续使用浏览器转写，直到本地 ASR 接入同一事件合约。

客户端提交的 MiniCPM 浏览器转写事件增加 `source=browser_asr`；百炼上游事件增加 `source=provider_asr`。Ledger 对同一 `turn_id` 只接受配置指定的权威来源。

### 轮次与消息合约

规范化事件增加以下可选字段：

```ts
type RealtimeEvent = {
  type: string;
  turn_id?: string;
  item_id?: string;
  response_id?: string;
  is_final?: boolean;
  source?: "provider_asr" | "browser_asr" | "provider" | "application";
};
```

百炼适配器保留上游响应、会话条目和转写条目的标识；本地 Provider 无标识时由适配器按候选人/面试官轮次生成稳定 ID。前端消息投影以 `turn_id + speaker` 更新气泡，不再依赖相邻事件猜测边界。

### 自动跟随最新消息

聊天区增加末尾锚点。用户距离底部不超过 80 px 时，新消息自动滚动到底部；用户主动向上滚动后暂停跟随，并显示“回到最新”图标按钮。点击后恢复自动跟随。

### 音频诊断模式

默认保持全双工。设置页提供非默认开关“模型说话时暂停麦克风上传”。开启后，客户端在收到第一段 `assistant.audio.chunk` 时暂停发送音频，在该响应 `response.done` 且本地播放队列清空后恢复。该开关只影响音频上传，不停止麦克风权限或候选人 UI 状态。

### 退出、结束和持久化

面试页提供两个明确命令：

- `退出面试`：二次确认后发送 `session.cancel`，保存状态为 `cancelled`，不生成报告，返回设置页。
- `结束并生成报告`：进入 `ending` 状态，停止录音，发送 `session.end`，等待服务端持久化完成。

服务端收到 `session.end` 后先停止 Provider，再将 Ledger 写入磁盘，最后发送：

```json
{
  "type": "session.persisted",
  "session_id": "iv_xxx",
  "status": "completed"
}
```

前端只有收到 `session.persisted` 才进入报告页。等待超过 15 秒时显示重试保存或返回历史记录，不直接丢弃本地会话 ID。

### Ledger 体积

Ledger 不再保存每个 8 ms 音频包事件。会话内聚合以下计数：输入/输出音频包数、字节数、首包时间、丢包数。转写、状态、错误和响应边界继续逐条保存。长面试文件目标小于 1 MB，不包含原始音频。

## 阶段二：面试编排

### 设置项

设置页增加：

- 时长：15、30、45、60 分钟，默认 30 分钟。
- 主题：综合面试、项目深挖、运动规划与控制、机器人系统工程，默认综合面试。
- 音频模式：全双工、播放时暂停上传，默认全双工。

这些字段随 WebSocket 握手进入 `InterviewContext`，并写入 Ledger 和报告。

### 阶段预算

综合面试按时长比例分配：开场 10%、项目深挖 45%、岗位基础 25%、压力与边界 10%、候选人反问和收尾 10%。主题面试把项目深挖和岗位基础合并为 70% 的主主题阶段。

客户端显示剩余时间和当前主题。服务端拥有权威开始/结束时间；客户端计时只负责显示。剩余两分钟时进入收尾阶段，到时自动发送结束指令并生成报告。

### 单轮问题约束

每轮由应用提供一个 `question_objective`，例如“核验 MCAP 如何定位轨迹拼接错误”。Provider 提示词要求：

- 只围绕该目标问一个问题；
- 中文不超过 80 字；
- 最多一个问号；
- 不使用“另外”“同时再说一下”等追加问题；
- 候选人迟疑时只允许简化原问题或换题；
- 不给答案、不总结候选人应该怎么答。

百炼在阶段切换时通过 `session.update` 更新当前目标和剩余时间。MiniCPM 在会话开始时注入完整短计划；阶段更新能力标记为 best-effort，不为此重置模型。

纯 Realtime 音频在说出后无法被应用撤回，因此长度和单问题要求属于强提示约束，不宣称绝对保证。若后续需要严格保证，单独评估“文本问题生成 + TTS”编排模式，不混入本阶段。

## 阶段三：证据报告

### 问答清洗

报告输入只使用权威 ASR 的 final 转写，并按 `turn_id` 配对面试官问题与候选人回答。过滤空白、纯语气词和完全重复项，但保留“不会”“未考虑”等有评价意义的回答。

清洗器标记而不删除以下风险：疑似角色串位、超长连续转写、缺少问题的回答、缺少回答的问题。报告必须展示转写质量和覆盖率。

### 评分量表

总分 100，目标 JD 岗位胜任度占 70 分：

- 岗位相关性：20
- 技术深度与正确性：20
- 工程证据与量化验证：15
- 问题分析、边界与安全意识：15

本场回答表现占 30 分：

- 回答结构：10
- 表达清晰度：10
- 诚实度、反思与风险沟通：10

每个维度返回 `score`、`max_score`、`evidence_turn_ids`、`rationale` 和 `confidence`。没有证据的岗位要求进入 `not_covered`，不直接计为零分；报告同时显示已覆盖分和覆盖率，避免短面试被伪精确评分。

已覆盖表现分按 `sum(score) / sum(covered max_score) * 100` 计算，岗位覆盖率单独展示。岗位维度覆盖率低于 60% 时，结果标记为“阶段性评分”，不能显示为完整岗位胜任度。这样既不把未提问内容当作候选人不会，也不允许少量高分回答掩盖覆盖不足。

### 模型分析与校验

报告模型接收 JD 摘要、岗位评分量表和清洗后的问答，不接收 14 万条传输事件。输出必须通过 Pydantic 结构校验、分数范围校验和证据 ID 存在性校验。

网络超时或 JSON 无效时：

1. 保留会话和清洗结果；
2. 返回 `analysis_status=failed` 和可读错误；
3. 页面提供“重新分析”；
4. 不写入能力树；
5. 不展示规则兜底为正式分数。

模型分析成功后，后端按量表权重计算总分，模型不能直接覆盖总分。能力树只吸收带有效 `evidence_turn_ids` 的技能和缺口。

### 报告页面

报告展示：总分与分母、覆盖率、分析置信度、各维度分数、优势证据、风险与缺口、逐条练习计划、完整转写。点击证据可定位到对应问答。生成期间只显示客户端能确认的“正在保存对话”“正在分析报告”“报告已完成”三个状态；失败时保留重试按钮。

## 错误处理

- Provider 连接失败不创建“已就绪”会话。
- 会话持久化失败时不关闭浏览器连接，并允许重试。
- 报告分析失败不覆盖已有成功报告，也不更新能力树。
- MiniCPM 重载中不创建排队 WebSocket，避免 45 秒后留下旧连接。
- 浏览器 ASR 不可用时，MiniCPM 明确标记“无候选人转写，不能生成正式评分”。

## 验收测试

### 阶段一

- 百炼会话不会启动浏览器 ASR；MiniCPM 会启动。
- 同一轮的流式文本始终合并到同一气泡，不同轮不合并。
- 用户位于底部时自动滚动，主动上滚后不抢滚动位置。
- `退出面试` 不生成报告；`结束并生成报告` 等待 `session.persisted`。
- 20 分钟模拟音频的 Ledger 小于 1 MB。
- MiniCPM loading/busy 时连接按钮禁用，idle 后可连接。

### 阶段二

- 时长和主题进入握手、Ledger 和提示词。
- 到达时间上限自动进入收尾并持久化。
- 迟疑回答不会触发示范答案。
- 测试提示词包含一个目标、80 字和单问号约束。

### 阶段三

- 报告只使用权威 final ASR，不包含浏览器重复转写。
- 评分维度合计严格为 100，JD 与本场表现权重为 70/30。
- 所有证据 ID 均能定位到真实问答。
- `ReadTimeout` 产生可重试失败，不产生正式分数或能力树更新。
- 最新长面试样本能够识别 MCAP、时间戳、五次样条、Slerp 等优势，以及缺少量化、安全约束和端到端延迟拆解等缺口。

## 非目标

- 本轮不修改 MiniCPM 模型权重或 Comni 的完整重载机制。
- 本轮不实现新的本地 ASR 模型。
- 本轮不承诺纯 Realtime 模型百分之百遵守单问题限制。
- 本轮不保存原始候选人音频。
